# Brainstorm Brief Template

Use only the fields needed to make the assignment unambiguous. This brief supplies Plan Gate; it is not a second execution gate.

```md
BRAINSTORM BRIEF

Objective:
Existing assets:
Constraints:
Assumptions:
Known unknowns:

Alternatives: <genuine alternatives, or why one adequate approach is evident>
Recommendation:
Why:
Decision status: <recommended / approved, with approval reference if available>

In scope:
Out of scope:
Affected assets:
Use existing:
Do not rebuild:
Success conditions:
Stop conditions:
Verification required:
Material risks:
Open decision / approval needed:
Handoff: <Plan Gate for state-changing execution, or the bounded non-state-changing assignment>
```

Name the existing asset and what must not be recreated. Prefer reuse when it meets the requirements. Make success and stop conditions observable. Remove accidental optionality without inventing authority or concealing uncertainty. Do not call a recommendation a locked decision.
